# 关卡试玩：场景故事流设计提案

日期：2026-10-06。状态：设计评估与效果稿，尚未实施业务或界面改造。

用户需求：让全局预演跟随关卡画布，将人物接触、交互对话、环境文本汇成可直观操作的故事流。沿用 NPCs AI Studio 暖灰、铜色工作台，不增加独立编排画布。

## 当前界面评估

依据用户本次提供的截图和 src/Rehearsal.jsx 阅读，未执行完整交互审计。

1. 进入预演：时间、已保存分支、分叉和初始变量同时出现，缺少清楚的试玩起点。
2. 接触人物：主体默认显示一个人物的派生状态；当前场景中还有谁、谁可以交谈不够直观。
3. 执行对白：可用性检查和条件树挤占对话区，没有形成连续的玩家/NPC交流记录。
4. 推进剧情：底部时间线、非对话文本、人物状态分别展示，用户需自行将它们拼成故事。

现有配色和人物/场景引用适合沿用。正文与条件说明字号偏小、不可用选项密集，需要在实现后验证对比度、键盘操作、焦点顺序和屏幕阅读器；截图不证明可访问性合规。

## 提议界面

- 名称：关卡试玩。全局入口允许选择关卡；试玩直接使用该关卡的已保存内容。
- 左侧：本次行程。显示实际到访场景、当前场景和尚未到访场景。尚未到访不代表强制下一步。
- 中央：当前场景的故事流。环境卡、简短事件提示、NPC发言、玩家选择依次记录；当前对白突出，历史对白弱化。
- 右侧：按当前关卡、场景、时间和条件筛选在场人物。单人卡可以交谈；NPC组展开各成员，环境台词可用“听听闲聊”触发。本场景非对话文本可展开阅读。
- 底部：关卡时间/阶段概览，显示当前时间与作者锚点，可定位来源关卡画布。
- 玩家状态在一个折叠入口中调整。试玩记录有独立可见入口；诊断、条件说明、旧分支及高级操作收进更多菜单。

配套效果图：level-story-play-concept.png。由内置 Image Gen 基于用户本次截图生成；内容、数量和布局为示例，不能视为当前项目真实运行结果。生成提示词保存在 level-story-play-prompt.txt。

## 推荐操作流程

1. 选择关卡与起点；默认采用关卡明确设置的开始位置，未设置时请用户选择，不擅自推断。
2. 进入场景，呈现满足条件的环境内容与已触发事件，展示当前在场人物。
3. 点击人物“交谈”，按正式对话入口规则启动，不自动替用户选择。
4. 点击玩家选项，追加玩家和NPC发言，结算效果并更新场景人物/可用文本。
5. 结束当前对话后，可以继续与其他人物交谈、等待或前往可选场景。移动与时间推进需要明确的玩家操作或作者规则。
6. 保存本次试玩为可查阅记录；提供现有恢复删除能力。重试基于当前编排，历史文本保持冻结。

“线性”指记录按发生顺序呈现；实际剧情仍允许分支、回访与不同人物接触顺序。场景轨道顺序不能自动当作移动路线。对话进行中切换场景需明确结束/退出交谈，避免静默丢失当前节点。

## 内容和执行边界

- 试玩复用关卡中的人物出场、NPC组、事件、对话绑定和文本条件；不复制角色资料、不改写正式故事。
- 关卡试玩遵守正式条件入口，角色工作台的临时卡片测试继续用于指定节点调试。两种入口在界面上明确区分。
- 预演不调用模型续写新剧情，采用已审核的文本和 Python 确定性执行结果。
- 人物行为备注并非可自动执行的行为。场景状态、出场引用与实际执行效果必须分别处理，不能仅凭备注推断剧情。
- 原执行器已有时间、场景、对白及效果结算；连续文本展演、在场人物聚合和关卡试玩完整记录还需专门实现，不能仅换布局就称为完成。
- 环境文本需要明确的展演顺序及重复策略。首次呈现/主动阅读/再次进入的行为应是显式设置；先提供简单默认与可追溯来源，不自行编造旁白。
- 每张已显示的内容卡可定位其作者来源。已显示历史不随作者后续编辑改写；重开试玩读取当前保存版本。
- 新记录与旧 simulation_cases 保持兼容，旧记录缺少历史正文时明确说明，不能补造过去对白。

## 建议落地顺序（待设计确认）

第一步：在场人物集合、故事流、选择交谈/选项/场景、环境阅读以及当前时间概览。

第二步：事件和状态变化嵌入故事流；会话冻结记录、重试、删除恢复；保留高级诊断。

第三步：等待/回访、环境重复策略及大关卡性能。中英文文本、键盘操作和所有场景门槛随各步验证。

验收重点：与关卡画布同一份出场条件；人物不在场时不能交谈；入口条件与角色工作台明确区分；一次性效果不重复；玩家选择按原图跳转；改变场景不会暗中跳过对话；历史记录不覆盖；不需要再次维护另一套关卡故事。
