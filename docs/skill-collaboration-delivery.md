## 工作流

新故事经过 AI 整理为 `ludo-storyboard` v1：世界、人物、场景、锚点、出场、NPC 组、关系、事件、对白与文本。compile 生成独立 v2 工程 ID，并创建关系画布和对白卡片布局；校验后导入新路径，不覆盖旧作品。原始故事和推断 notes 一起交付；notes 不写入工程剧情。

已有工程通过会话保护的 `GET /api/v2/projects/{id}/author-context` 读取同一快照的 Project 与 author_hash。AI 提案使用准确 revision/hash；桥接预先校验完整候选与草稿，然后提交 pending 记录并保存。正式字段保持原值，作者在草稿审核中决定采用。由服务端生成作者摘要，避免客户端复制摘要规则或草稿新增修订导致立即过期。

`LudoNPC.exe --skill-bridge` 与分发 Python 脚本采用同一核心，仅在桥接模式下连接已运行服务，不额外启动服务。正常启动方式保留。助手无需 NPCs AI Studio 的 API Key，也不读取模型配置。

## 边界

普通云聊天不能直接连接用户电脑的 localhost；只有本地执行工具可调用桥接。没有本地能力时只交付内容/文件，不声称已保存。各 AI 产品的自动发现/安装路径尚未逐个平台验收。

当前草稿桥接覆盖人物、地点、阵营、事实、变量、事件、规则、对白、文本实体。世界底稿、关系、关卡结构和初始状态暂不通过该候选格式修改。新候选不能引用其他尚未采用候选，需分轮采用依赖或生成完整独立工程。没有 MCP 或外部创作文件的专用导入弹窗。

Windows 内置桥接仅在本批程序包提供；早期包没有这个命令或作者上下文接口。本机 EXE 验证不等于干净机器验收。两版说明和原始故事对应示例结构，但本轮未验证独立第三方 AI 在所有题材上自主转换长篇故事的质量。自然语言泄密与世界观一致性仍需作者审核。
