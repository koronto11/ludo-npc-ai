# 关卡与剧情融合 · 2026-10-06

人物出场、剧情事件和规则围绕同一个关卡导演台操作。移除顶栏独立“剧情规则”入口，保留原有世界事实、变量、初始状态与文本编辑能力，集中到同页侧栏。

## 使用方式

- 场景轨道的“剧情事件”直接创建该场景的事件；“添加事件”创建整个关卡的事件。卡片显示时间阶段和预演状态，支持左右拖动改期、上下拖动换场景、局部撤销/重做。整个关卡的事件使用单独的关卡剧情轨道。
- 卡片“条件 / 效果”打开侧栏的三个步骤：触发时机与范围、组合条件、执行效果。规则列表可查看本关卡、全局或所有关卡，支持搜索、编辑、停用和重新分配关卡/场景。
- 事件可绑定现有时间锚点。移动锚点由 Python 同步更新事件时间；删除锚点保留事件时间并解除绑定。拖动事件会绑定新位置恰好匹配的锚点，否则使用独立时间。关卡撤销恢复关联事件的时间、场景和锚点；提交剧情定义后清除旧安排历史，避免后续撤销覆盖新定义。
- “预演”在同页切换故事时间、场景和测试变量，展示触发条件、人物状态与变化记录；可以保存、放弃、分叉预演输入，或进入人物对白工作台。预演改变测试分支，不修改人物主档案。
- “全局规则与资料”提供没有关卡范围的规则与事件；“事实与变量”保留事实、变量、初始状态、非对话文本和无所属人物的对白编辑。所属人物对白仍可从人物进入角色工作台。
- 人物出场详情和关系画布属性栏展示关联剧情。关联包括显式标记人物与实际人物效果目标，点击可定位对应关卡并打开编排侧栏。
- 未保存的剧情/资料编辑会阻止关闭侧栏、切换对象和工作区，并提供保存或放弃。窄屏侧栏占满工作区；桌面编排侧栏与场景轨道并排。

## 数据与执行边界

`Event.scope` 与 `Rule.scope` 是可选的关卡/场景引用；事件另有可选 `anchor_id`。Python 校验引用和锚点时间，并在执行规则与展示触发原因时验证当前预演关卡、场景。共享同一个世界地点的其他关卡不会触发该关卡的剧情。

旧文件未包含这些字段时保持全局行为。空默认字段不改变旧作者指纹，也不会因为读取旧工程使待审核草稿过期。数据仍保存在用户本地 JSON；未解决剧情引用时不能删除其关卡或场景，需先调整事件/规则范围。

事件和规则仍在每个分支中各触发一次；未到时或条件不满足的事件继续等待。这里没有新增任意脚本、循环规则、等待/并行流程或自动关系变化。场景关联限制当前预演场景，不会自动推进玩家进入下一个场景。全局预演没有关卡上下文时不执行关卡专属剧情。
