# 场景批量创作闭环

2026-10-06。本轮围绕「场景提出需求 → 生成候选 → 审核采用 → 找到内容 → 编辑与试玩」补全路径。

## 使用路径

1. 在关卡画布的场景轨道点击「背景 NPC 组」，或在「场景内容」点击「批量创作」。
2. 选择环境对白池或独立背景人物，填写组名、数量、身份、出场时间、口吻和话题边界。提交前显示本次名单与采用去向；模型选择收进执行设置。
3. 提交后打开本批草稿审核，按生成批次隔离候选与进度。默认展示对白正文、对白卡片和选项；字段差异、结构字段及条件保留在高级编辑。
4. 可编辑环境对白并保存候选，然后采用本批已保存草稿。逐字段审核、确认字段保护、拒绝及过期重新比较仍然有效。
5. 采用结果提供「查看内容」「编辑与试玩」「查看本批所在场景」。场景内容集中显示待审核候选、环境文本和人物出场对白；同一人物的多次出场分别保留。

## 数据与安全边界

- `SceneGenerationContext` 保存关卡、轨道、世界地点、出场、时间范围、组名及生成方式。生成任务项与草稿共享该来源，失败项重试保留来源与时间。
- 环境对白池不建立人物档案。文本的场景归档使用来源区分相同地点的不同关卡轨道；实际出现条件仍使用已有地点与时间条件，没有新增关卡文本条件算子。
- 独立人物模式先原子保存轻量人物与出场；生成失败保留这些作者记录，同窗口再次提交复用名单。关闭后重新发起属于新批次；失败任务可从任务记录重试。
- 采用对白时，Python 在同一事务中创建对白并绑定指定出场。旧空白对白列表原本表示所有适用对白，改成显式列表时保留这些既有对白。
- 请求前及采用时校验目标仍存在、场景地点未变化、人物与出场相符、时间包含关系有效。来源不能通过候选编辑改写；最终项目校验失败时整个采用事务回滚。
- 一个批次最多 10 项、最多 2 项并发。批量采用只处理当前范围中已保存的候选，生成过程中及候选未保存时禁用。作者设定变化仍要求显式重新比较。
- API Key 留在页面会话与请求内存，未增加外部存储。旧草稿缺少场景来源仍可读取，已接受草稿的历史来源不要求被删除的引用重新存在。

## 验证

- 全部 Python 测试：209 项通过，其中新增 9 项验证环境文本/独立人物批量采用、精确出场绑定、原有默认对白保留、存储重开、目标变化拒绝与事务回滚。
- 全部前端测试：77 项通过，其中新增 5 项验证名单及生成计划、同地点跨关卡隔离、多次出场导航、失败项重试参数。
- Ruff、生成契约一致性检查与生产构建通过。
- 浏览器使用独立本地项目与明确标记的协议夹具验证：2 项环境对白生成、候选修改与保存、批量采用及场景归档；5 位背景人物生成、批量采用、进入对应出场工作台、开始试玩与执行选项。
- 用户工作项目没有加入测试人物或协议示例。没有调用真实外部模型；兼容性、自然语言质量、数量遵循和内容多样性仍需用户在应用内配置有效模型后验证。
