# 角色试玩交互收敛评估

日期：2026-10-06。范围：角色工作台右侧试玩、重开操作及测试条件；本次仅评估，不修改应用代码、人物对白或测试记录。

目标：设计师在开场对白中测试“玩家受伤”为是时的第二个选项，不必理解测试分支或修改开场规则。

## 当前流程与证据

1. 选择重新测试入口：不清晰。用户提供的 `01-restart-actions.png` 同时显示“按场景重新测试”“重新开始”“撤回本次重开”和“定位节点”；两个相似主操作要求用户判断执行范围。
2. 展开测试设置：负担较高。当前页的 `02-current-settings.png` 同时显示时间、场景、玩家变量、调整开场规则、已保存分支，以及底部应用/取消。基础试玩、作者配置和记录管理占据同一窄栏，挤压对白和选项。当前截图已显示默认开场和受伤为是，不声称其仍有旧的条件入口跳转问题。

现有优点：对白与玩家选项已分区；条件原因已有简短提示；完整调试信息可独立访问。保留这些结构。

## 建议方案（尚未实现）

- 默认右侧为“卡片试玩”，从对白的默认开场卡片开始，明确标记试玩起点；其他卡片可在右键菜单选择“从此处试玩”。卡片试玩可以不执行条件入口路由，但不修改作者的入口配置；卡片/选项的条件与效果仍需验证。
- 固定区只保留一个“试玩/重新试玩”主按钮。移除画布下方重复的重新测试入口；定位与撤回收进更多操作。
- 场景和时间先取当前出场上下文，折叠后可修改。优先显示当前对白相关的玩家状态；复杂条件仍允许展开必要变量。
- 不可选选项下面就地展示阻塞条件，并提供明确的状态调整入口。简单布尔示例“玩家受伤：否”可直接切换；复合、时间、知识等条件不自动伪造满足结果。
- 试玩中调整玩家状态只更新本次临时状态并重新检查当前卡片/选项，保留当前卡片，不重新匹配条件入口，也不重复执行卡片进入效果。若当前卡片本身不再符合条件，给出可见提示而非悄悄跳转。
- 不因每次试玩选择而要求保存分支或阻止页面切换。显式保存测试案例、完整剧情入口验证、回放记录和详细条件树统一放入高级调试；作者编排未保存的保护继续保留。
- 开场规则的编辑留在画布入口卡片配置；玩家选项条件留在对应选项配置。日常试玩面板不展示作者规则编辑快捷键。

建议的常见任务：试玩开场 -> 在灰色第二选项旁将玩家受伤切换为是 -> 点击第二选项 -> 查看处理伤口对白。全程不修改对白入口规则、不保存测试分支。

## 可访问性与评估限制

截图中次级文字与背景的差异较小，状态说明和小图标存在阅读/点击负担。建议清晰文字标签、足够大的触发区域和就近状态反馈，条件变化需支持键盘操作和读屏提示。

本次捕获当前页面和用户提供的截图，未修改页面控件、未测键盘/读屏、未测量对比度，也未执行完整剧情验证；这些是设计建议，不能视为已实现行为或完整可访问性结论。
