# 预演测试与开场规则操作优化

此前修改测试变量会立即重放已有选择记录。若变量同时影响条件开场，角色会改从另一张卡片进入，旧选项记录可能失效，用户也难以判断跳转依据。

## 新流程

1. 打开“测试设置”，调整故事时间、场景和初始变量。设置先保留在面板中，下面继续显示上一次结果，并明确标记“尚未应用”。
2. 点击固定在面板底部的“应用并重新开始”。建立一个新的临时预演分支，只包含当前对白的开始记录，不沿用旧选择或场景切换记录。时间前的故事事件与规则仍由 Python 正常计算。
3. 根据真实开场规则进入对应节点。条件开场的依据可展开查看，“调整开场规则”直达同页编辑面板。
4. “撤回本次重开”恢复上一次测试前的变量、时间、场景、选择记录及未保存状态。仅保留一层撤回；保存分支、切换场景或项目后撤回入口清除。

“开场规则”编辑面板明确区分默认开场与优先匹配的条件开场。“仅使用默认开场”会移除当前对白的条件开场，保留所有玩家选项上的条件。它是作者修改，需要保存编排后才影响预演；修改前的工程仍由本地备份保护，未保存时可放弃编排。

角色工作台中的预演输入和待应用设置也接入页面顶部离开提示。保存成功才跳转；放弃可以直接切换场景；取消保留当前位置和输入。收起预演使用同样的保护。画布底部“按场景重新测试”同样创建新测试，避免被旧分支输入阻挡。

## 数据与执行边界

- 项目 JSON 输入契约未改。Python 模拟输出新增 `dialogues[].entry_preview`，说明当前状态下再次开场将选择的节点、条件序号和判断原因。
- Python 按条件开场优先、默认开场兜底的执行顺序保持不变。前端不复制条件执行器、不强行绕过出场或节点条件。
- 调整设置、临时测试和撤回均不自动保存项目。明确保存预演分支或选择“保存并跳转”才写入本地 JSON。
- 一键切换固定开场在独立验证工程进行。主体验工程保留用户的条件开场、角色、选项和布局。

## 验证

- 前端 66 项测试通过：新增设置暂存、空场景、独立分支、旧记录隔离和数字验证覆盖。
- 后端 189 项测试通过：新增条件开场说明与执行一致、默认节点条件保护覆盖。
- 构建、Ruff、7 个契约及示例文件一致性检查通过。
- 实际浏览器验证：勾选变量不立即跳转；显式应用后条件开场显示原因；新测试无旧选项冲突；撤回恢复“旅途闲谈”及原选择记录。
- 独立本地工程验证“仅使用默认开场”并保存后，玩家受伤仍从问候开始，主动选择受伤选项后才进入处理伤口。
- 验证待应用设置“保存并跳转”、预演输入“放弃并跳转”、画布重新测试以及短窗口固定操作栏。验证页控制台无 error/warn。
