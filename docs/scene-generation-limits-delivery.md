# 场景台词生成数量与用量边界

## 用户操作

“每人句数”改为“每人对白卡片数”，支持 1–6 张，默认 2 张。开场与全部分支都计入，玩家选项不计入。一张卡片正文可以包含多个句子。

另外选择每张台词长度：简短（最多 120 字符）、适中（240）、详细（480）。包含标点与空格，按 Unicode 字符计数。默认简短。

提交前实时显示人数 × 卡片数的总量，以及本次请求单项输出 tokens 上限，包含正文、选项和 JSON 结构。该上限为模型配置上限与按所选规模计算的预算二者较小值，不改写模型配置，也不宣称是费用估算。无指定人物的环境文本只选择每份长度，不显示卡片数量。

## 服务端行为

- 可选 typed `GenerationItem.output_limits` 保存 `card_count` / `text_length`。不带限制的旧请求及已生成草稿保持兼容。
- 调用前校验类型与范围；不合法设置不会调用模型。
- 每个请求传入明确数量、正文长度、收紧的实体 Schema；provider profile 的 `max_tokens` 使用本次副本，不改变保存的配置。
- 响应要求 `nodes` 精确达到所选长度，各正文不超长。未达要求时，仅该项失败，说明要求与实际数量。不会截断有引用的对白图，也不会再调用模型自动修补。
- 失败项仍累计服务商返回的 usage；成功草稿保留。手动重试复制保存的限制，只重试失败项。旧任务没有限制时不臆造它原来的设置。
- 这是输出约束，不能保证第三方模型必然服从，也不能撤销已发生的费用；连接临时失败的重试仍遵循用户已有模型配置。
