# 多结束节点

角色工作台的「结束节点」按钮创建独立结局，可命名、拖动、编辑说话者与收尾台词。玩家选项的目标列表区分普通对白和结束节点；不同分支可选择不同结局，也可共享一个结局。快速文本与画布共用草稿、保存和离开保护。

进入结束节点后，Python 执行其条件与进入效果，输出非空的 NPC 收尾台词，然后关闭对话；不增加玩家选项。收尾台词留空则直接结束。节点名称、台词与结束帧进入冻结试玩记录；全局预演同样执行该流程。Markdown、CSV 和模板保留结束类型及跳转关系。

复用 DialogueNode，增加可选 node_type（speech / ending），结束节点必须没有 options。普通节点的默认类型在序列化时省略，旧项目及候选基线保持原有形状和 author hash。旧 target_node_id=null 保留直接结束语义；旧的无选项普通卡片不自动转换为结束节点。无需迁移既有项目。

删除结束节点需要确认，指向它的选项改为原有直接结束目标；保存后的共享撤销恢复节点及引用。布局仍使用原有 editor.dialogue_layouts，不修改剧情拓扑。明确的结束节点计入 AI 生成的每人卡片数；玩家选项不计入。没有调用真实模型验证输出质量。

验证包含两种独立收尾、空台词、旧直接结束、条件阻止与效果回滚、入口结束、全局执行、旧格式与哈希、非法选项、模板及导出。独立浏览器测试创建两个结局、设置分支、快速文本编辑、美化与保存，验证 NPC 收尾后关闭、冻结记录、确认删除、撤销恢复引用及刷新重开。测试项目与作者原文件分离。
