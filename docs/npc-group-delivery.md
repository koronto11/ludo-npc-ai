# 场景 NPC 组改进

关卡画布的场景轴现在提供“添加 NPC 组”。默认建立 1–10 个人物档案、一组场景出场与一个组控件；仅创建无需 API Key 或模型请求。角色仍是共享文字档案，会出现在人物总览与关系画布。

组控件支持展开 / 收起，显示每人的身份、出场时间、正式台词摘要与审核状态。点人物名称调整单人出场，点“编辑台词”手工修改，点“审核”直接弹出此人的候选内容，点“编排 / 试玩”进入原有角色工作台。手工台词和可读草稿正文均能直接编辑，修改保留原有选项、条件与效果；手工修改共用对白会同步到其他引用它的出场。

“批量生成台词”沿用原人物与出场，不重复建角色；有已有专属对白时生成候选修改，审核前保留旧台词。每个模型请求明确限定一个人物，Python 校验节点说话者，拒绝其他人物 ID。无说话者的节点补为本项人物。自然语言中冒用其他身份仍需作者审核，结构验证不能证明模型文本质量。

组标题可拖动时间与场景，保留个人间隔与时长。组设置支持名称、场景和统一时间范围，解散只拆掉分组，保留角色、出场、对白，可用关卡撤销恢复。移动出场不会自动改写已有对白的故事条件；如已采用台词带固定时间 / 场景条件，需在编排中核对。尚未采用的候选仍保留原生成范围，目的出场变更后会拒绝错误绑定。

高级“无指定人物的背景文本”沿用文本池方式，只创建场景文本草稿，不创建人物或组控件。旧项目的匿名草稿原样保留。新增 `Level.npc_groups` 和 `Appearance.npc_group_id` 缺省为空；旧文件仍可加载，空缺省不改变旧作者指纹。组成员与组必须属于同一个场景，引用由 Python 校验。全部数据仍在本地 JSON。

验证：后端 225 项、前端 94 项测试通过，Ruff、合同生成检查和生产构建通过。独立本地协议示例验证离线创建三人组、手工台词保存、关闭未保存提示、组内草稿微调采用、重复生成更新原对白、重载恢复、整体拖动、解散与撤销。验证没有调用外部模型，没有修改用户现有项目。
