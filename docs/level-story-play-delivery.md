# 关卡场景故事流交付

日期：2026-10-06。范围为全局预演的中间工作区与右侧人物面板。用户指定保留左侧作者资料库、底部 RuntimeTimeline 与其四个页签，本次未改写该组件。

## 使用方式

1. 打开顶部“全局预演”。点击“玩家状态”，选择关卡、起点场景、故事时间与本次初始变量，“应用并重新开始”。已保存的试玩直接重开，未保存的试玩会先询问保存、放弃或取消。
2. 右侧仅展示 Python 判定为在场的出场引用，按角色和场景 NPC 组聚合。点击“交谈”，在中央当前对白卡上选择回答。没有对白或未满足对白条件的角色仍显示在场并解释不可交谈的原因。
3. 进入场景、成功执行的事件/规则、环境文本、NPC 正文与玩家回答构成可滚动故事流。下方操作条可等待一个单位、推进至下一个关卡时间锚点或前往其他场景。离开未结束交谈先确认，既有操作和正文留在流中。
4. “试玩记录”保存不可覆盖的文字快照，查看、可恢复删除及恢复都在同一弹窗中。重放采用当前内容执行原输入；旧快照保留。旧 simulation_cases 显示已保存条件和操作路径，明确没有历史正文。角色卡片试玩仍在角色工作台管理。
5. 更多菜单保留重开、调试、定位作者编排等操作。未保存试玩离开工作区时复用顶部保存/放弃/取消守卫；保存成功后才跳转。

中英文控制台帮助和 docs/user-guide-zh.md / docs/user-guide-en.md 已同步。

## 执行与存储

- 复用关卡出场与正式对白入口；不会为了让选项可用而改写条件。玩家状态在此界面是一次新试玩的起点，角色工作台保留在当前卡上调整变量的原有测试方式。
- 新响应 story_flow 提供展示来源（场景、文本、事件、规则、对白）与人物引用。原 log、transcript、事件一次性触发与 card_trial 协议保持兼容。失败事务回滚已经追加的展示帧。
- 环境文本每次场景访问最多呈现一次，只在条件和解锁同时通过时出现，回访可以再次出现。时间条件边界纳入回放步长，避免跳时间时漏掉短暂可用文本。不会根据人物行为备注自行编造活动或旁白。
- 保存使用现有 editor.play_records 和 typed PlayInputs / PlayFrame，不新增数据库、外部服务或协议迁移。临时试玩操作不修改作者内容；记录与删除标记仍由现有本地 JSON 保存流程处理。
- 故事流显示上限 2048 帧并单独提示截断，执行结果的 complete 不因显示截断改变。受现有记录契约限制，单条冻结记录上限 384 帧，超出时禁止保存并提示缩短范围。
- 试玩不调用模型。本轮没有发送外部模型请求，也没有修改模型密钥。Windows 分发包没有在此轮重新构建或进行干净机器验收。
